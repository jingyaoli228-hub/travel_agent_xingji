你在我的「行迹 · AI 旅行规划」仓库里工作（微信小程序前端 + Python/LangGraph 后端，部署在国内腾讯云，地图和路线用高德 Web 服务）。这一轮的目标是：按 P0 原型重做小程序前端，接入 UI 组件包，并补上 P0 需要的后端接口。不做任何 P1 功能。

资料都在仓库根目录的 docs/xingji-p0/ 下：
- PRD_v2.md：需求的唯一依据。先读「范围决定」「UX 评审结论与 PM 决定」「P0 原型」这三节。

请按下面的顺序做，每一步做完都停下来，给我一份简短的报告：改了什么、怎么验证的、还剩什么。等我确认后再做下一步。

第 0 步，只读，不改代码。读完上面的资料和现有代码，给我一张对照表，列出每个 P0 页面或状态：现有代码里对应哪里，打算新建、改造还是删除，需要哪些后端接口，现有接口能不能满足。标出 PRD 和原型之间的矛盾，以及原型和现有接口之间的矛盾，矛盾不要自己猜着定。另外按 PRD 的「做减法」一节列出要删的代码。

第 1 步，接入组件包：把 styles/、components/、utils/map-style.js、assets/markers/ 合进项目，不要覆盖我的 app.js、project.config.json 和 appid。删掉 tabBar，行程页设为首页，用 xj-nav-bar 自定义导航栏。在开发者工具里能编译，kit-demo 页能正常显示。

第 2 步，做行程页首页（02 A–F）：原生 map 组件画出当天的点和高德路线，xj-day-tabs 带「今天」自动选中，三档抽屉，单一提醒位（优先级 错误/降级 > 质量 > 风险），质量徽标，合并节点卡，对话记录可以撤销，离线时只读并显示静态路线图，高德失败时走降级态。

第 3 步，做主流程（P10）：空态 → 偏好轻确认（历史预填，必去和不想去每次都问）→ 规划进度（按天流式填入）→ 景点确认（只在装不下时出现，超出的进候补）→ 草稿。规划失败或质量不达标时，绝不能显示「规划完成」。

第 4 步，做加地点（03）和玩法卡（05）：用现有的 preview-insert、apply-patch、rollback-patch 接口实现预览插入、冲突卡、当天重算和撤销。玩法卡先用北京 top20 的版式加示例数据，数据结构放在单独的 JSON 里。

第 5 步，做我的行程（06）、小红书粘贴导入（08）、Agent 透视（09）和异常态（11）。每次规划单独保存，带上它自己的对话记录，永远不覆盖之前的；已出行的行程只读，可以「复制为新行程」。

全程要遵守：
- 只用原生小程序。不用 web-view（个人主体用不了），不接谷歌任何服务，坐标统一用 GCJ-02。
- 颜色、字号、间距全部走 tokens，不要写死；两种橙色严格分工。
- 本地缓存遵守单个 key 不超过 1MB、总共不超过 10MB，离线缓存按行程拆成多个 key。
- 不做 P1：门票预约跳转、预约提醒、导出图片、小红书在线搜索和每日爬取、单独的「今天」视图、我的偏好页、选酒店和选餐厅。
- 每一步用单独的 commit，commit 信息写明对应原型的编号。
